# 出片方法（默认按这个来）

这份文档写的不是"能做什么"，而是**遇到问题先做什么**。荆门关那支一分钟片子的两轮返工，把下面这些
从"经验"变成了"默认动作"。违反其中任意一条，都要在结论里写明理由。

## 工具的选择顺序

一个镜头达不到要求时，按这个顺序升级，不要跳级：

| 顺序 | 手段 | 什么时候够用 | 成本 |
| --- | --- | --- | --- |
| 1 | **改静帧** | 人物长相、服装、场景构成不对 | imagine 一次 ~13s |
| 2 | **改提示词** | 动作方向、镜头运动、环境运动写得不够具体 | 0 |
| 3 | **上 ControlNet（灰模）** | **构图与物体空间关系**需要被外部钉死 | 灰模 20–30min + 出片 11min |
| 4 | **换构图** | 关系复杂到一帧说不清（例如"梁插进方孔"用中景永远含糊） | 改分镜 |
| 5 | **换素材** | 这一镜确实不该由模型做（改用录制/三维/图表） | 视情况 |

关键判断：**如果是"东西在哪、往哪动"的问题，第 3 步；如果是"东西长什么样"的问题，第 1 步。**
纯靠提示词硬拗空间关系，就是这次的教训——梁永远像贴在崖面上。

## 五条硬规则

1. **静帧先出、再让它动。** 人物一致性在静帧那一步解决（逐张核过再进视频），视频模型只负责让这张图动起来。
   视频提示词不要再描述长相。
2. **画面里不许有字。** 旗幡、木牌、门额、墙面都会长出伪汉字。提示词里写死"画面中不要出现任何文字"，
   所有旗幡木牌都是空白素面。`prompt lint` 的 `prompt.signage-leak` 盯这条。
3. **背景必须有自己的运动。** 只写前景动作，模型会把背景当贴图：人在动、河面浪花却静止。
   每镜都写一层：水纹流动、白浪推进、雾在卷、云在移、火星上飘。`prompt.static-background` 盯这条。
4. **动作要写接触关系。** 「凿」「锤」这类动词不写接触点，模型就让凿子直插石头、木槌砸在手背上。
   写"以 45–60 度抵在石面浅槽里、凿尖嵌在槽口不刺入、木槌与左手留出空隙"。`prompt.physics` 盯这条。
5. **分三层写。** 前景（虚焦的背影、晃动的绳）→ 中景（主体动作）→ 远景（河谷、山脊）。
   这是让模型产生纵深与视差最便宜的手段。`prompt.layering` 盯这条。

## 每次改动都要过审片

```bash
filmbench prompt lint                     # 四条规则
filmbench review-shot --shot <id> --open   # 九宫格：抽 9 帧（按镜头时长等分）+ 机器规则
```

九宫格不是走过场：水没动、绳没系、锤子砸手、构件穿透，这些问题一张图就看得出来，机器判不了。
看完把结论用 `--finding "..."` 落进事件日志——**下一个 agent 能读到上一轮为什么重拍**。

## 灰模（控制视频）怎么写

- 亮度当深度用：255 = 贴脸，20 = 远景；按画家顺序做 alpha 覆盖（不是取较亮者，否则远处的洞画不到近处崖壁上）
- 只描述"东西在哪、往哪动"，不描述材质、光、风格
- 首帧与正式出片的静帧对齐；长度与镜头帧数一致
- 参数从 `strength 1.0 / start 0 / end 0.6` 起：后半段放开让模型补细节
- 参考实现：`filmbench-demo/jingmen-site/scripts/make-control-h4.py`

```bash
filmbench shot control --id h4-cliff --video control/h4-cliff-control.mp4 --strength 1 --end 0.6
filmbench jobs submit --shot h4-cliff && filmbench jobs run
```

## 把钱花在能验证的地方

- 出片前先 `filmbench check`，出片后 `review-shot`：一次重拍 11 分钟 / 0.8 CU，返工两轮就是 1.6 CU 外加一小时
- 长作业断连别急着重跑：`filmbench jobs collect` 把远端已产出的文件收回账本
- 会话中途被杀：`colab up` 会续装，不重建、不重下模型
